# 申请书绘图

默认流程：**整理内容与插入位置 → 展示三个模板供用户选择 → 锁定模板并逐槽填入内容 → 保存绘图 Markdown → 生图与内部审核 → 用户确认**。多幅图逐幅执行；PPT和文档插入按用户原任务的交付要求处理。

## 任务与状态

先读取材料、现有运行记录和用户已确认的偏好，明确图的用途、输出格式、字体及印刷尺寸。用户已选择的模板、认可的图片和授权的调用路径在后续轮次继续有效。

新任务运行 `python scripts/init_run.py <任务名> --workspace <workspace>`，创建不覆盖旧文件的运行目录。续作沿用原目录。四个工作文件分别承担以下职责：

| 文件 | 内容 |
|---|---|
| `01-content-spec.md` | 本图目的、来源、内容摘要、节点关系、插入位置、与相邻图的边界 |
| `02-reference-selection.md` | 每轮A/B/C候选、用户选择、模板不变量、逐槽替换和连线清单 |
| `03-image-prompt.md` | 当前完整可提交的绘图指令；每次调用另存版本快照 |
| `04-feedback-log.md` | 原话、调用与版本、内部审核、修订结果、用户确认及交付状态 |

单图状态依次为：待选模板、已选模板、已完成指令、候选待审、用户确认、已交付。用户选定模板即授权按该模板生成本图，无需再要求审批绘图指令。“挺好的，开始下一幅”等同义表达确认当前候选；只问进度或只打开文件不构成确认。

多图任务先列已明确图片的图号、标题、对应段落与摘要；尚未提供的后续内容暂记待定，不阻塞当前图选型。各图分别记录状态与版本，避免复用上一幅的选择或把未确认候选插入最终稿。

## 1. 整理本图内容

读取申请书相关段落及必要上下文，填写`01`：

- 用一句话说明评审应从本图看懂什么，再提炼层级、节点、关系和输出。先总结内容，再匹配模板。
- 文档配图记录章节、段首锚点、拟用图题和编号；多图应各有侧重，避免重复同一架构。
- 区分拟研究的方法、预期目标与已取得结果。术语、数字和技术边界以材料为依据，参考图不提供项目事实。
- 每条关系明确起点、终点、方向和语义。流程、并列约束与反馈分别表达，不能为填满模板而编造联系。
- 节点用短语，普通节点尽量不超过两行。未知事实留待确认，不生成假论文、成果、实测图或照片。

会改变核心图义的缺失信息先问一个关键问题；其余合理处理记入规格，继续准备候选。

## 2. 展示模板，让用户选择

参考目录为本skill的`references/`；`@refereces`按同一目录处理。可先缩小范围：

```powershell
python scripts/match_references.py <run>/01-content-spec.md --references <skill>/references --top-k 6 --out <run>/candidate-round-01.md
```

脚本只给主题相似度排名，不能代替布局适配判断或用户选择。将人工筛选结果写入`02`：

1. 默认提供**三个不同模板，编号A/B/C**。同时考虑内容关系、信息容量、印刷可读性和布局差异，不只取分数前三名。
2. 每个候选都先读同名Markdown并查看PNG。读取实际像素尺寸与比例，不凭预览估算。参考说明与PNG不一致时，以实际图片核查版面、按正文确定关系，并在02记录差异，不能照抄参考说明中的错误概括。
3. 向用户展示**原模板图片**，各配一两句说明内容怎样放入、适合突出什么，可推荐一个。使用可显示的本地图片绝对路径或原生图片展示工具，不能只列ref名称。
4. 提供候选后等待选择，此时不生图。用户说“再换三个”时，保留旧轮记录，优先排除已展示模板，另给三个；A/B/C仅对应最新一轮。
5. 用户直接指定有效模板，或明确授权助手自行选定时，记录该指示后进入下一步，不重复要求选择。

模板不足三个或都无法承载内容时如实说明，给出可用项；只有用户授权从零设计或调整版式时才走该分支。

## 3. 锁定模板，生成绘图 Markdown

选定后补全`02`的**逐槽替换表**和**连线表**，再填写`03`。不要停在“借鉴风格”的概括描述。

逐槽写明原位置、替换文案、来源、概念示意和保持不变的部分。默认保留原模板的画布比例、层数、行列、框体位置与大小、核心几何、配色和连线路径；用本项目内容替换既有槽位。原图位可换成相关概念示意，原项目文字和事实全部移除。风格辅图只负责字体或局部表现，不混入另一套布局。

连线方向必须符合正文关系。模板中的反馈或双向关系若不适用，应在选型时识别；不得保留错误图义。箭头端点、文字适配等不改变整体布局的小修正写入指令和日志。需要重排版面时回到选型或取得用户对该变更的指示。

绘图指令应能独立提交，至少包含：

- 本图目的、精炼后的内容、拟研究/已有结果的事实边界。
- 按实际传入顺序列出每张图片的角色：**编辑底图、当前候选、字体参考、局部示意参考**。
- 实测宽高比和目标尺寸。模板锁定时等比放大，不套用默认16:9；只有从零设计才另选画布。
- 各槽位必须逐字出现的文字、明确换行，全部节点和箭头的对应关系。
- 不变量、当前要改的内容、白底或透明要求、字号和禁用项。
- 真实素材的来源；没有素材时使用清楚的概念示意或诚实占位，不能伪装成实验结果。

文档配图优先匹配正文中文字体及相近的印刷字号。记录最终插图宽度，按`像素em ≈ 字号pt × 图片宽px ÷ 印刷宽in ÷ 72`估算文字规模，再查看实际输出。空间不足先缩短文案、合理换行，不靠小字塞满框体。AI栅格可检查宋体等字形外观，不能声称已嵌入或严格验证某字体文件；用户要求精确字体时采用可验证的文字排版交付方式。

保存完整`03`及本次调用快照，如`image-prompt-v01.md`。后续编辑保留原规格，另存`edit-prompt-v02.md`，使每次调用能追溯。

## 4. 生图并先做内部审核

读取已安装的`imagegen`skill。默认使用当前内置生图工具，按指令传入选定模板PNG和必要辅图。编辑本地目标前先查看该图；将绘图Markdown的正文作为提示词，不以一句简写替代已整理的规格。

用户指定模型时保留该要求；若接口支持型号选择，按实际可用参数指定。接口未披露型号时简短说明一次，记录实际工具与未核验状态，不把内置后端声称为已验证的指定型号。用户已选择继续用内置工具时直接沿该路径工作，不反复要求密钥配置。只有用户选择CLI/API路径时才检查相应配置，不索要对话中的密钥，也不静默更换模型。

每次生成后，将实际工具返回的图片复制到`images/<图号>-vNN.png`，保留旧版和原输出。在`04`记录提示词版本、输入图片、实际调用路径、输出路径和状态。多图一图一次调用，按当前图的确认流程推进。

交给用户前检查：

- 标题、全部中文、关键术语和数字逐项准确，无错别字、乱码或原项目残留。
- 每条箭头的起终点、单向/双向和语义正确；尤其核对渐变箭头是否意外生成双端尖头。
- 结构、槽位和配色符合所选模板，没有新增面板、通用照片图标或无依据曲线。
- 实际PNG比例与原图相符；锁定比例时以相对偏差不超过约1%为复核参考，不能凭提示词声称已满足。
- 缩放到预定插图宽度后文字仍可读，无遮挡、越界、过密小字；需要白底时确认透明空隙没有呈现黑底。
- 科学关系和时序成立，拟采用方法没有被画成已经完成的成果。

发现缺陷先针对性编辑当前候选，保留其他部分。不要因工具返回成功就把问题记为已处理。若同一局部连续两轮未改动，改用明确区域、坐标或“擦除并重画该连接”的指令；必要时简化局部箭头表现以澄清方向，记录差异。仍未解决时明确保留问题，不无限盲试或冒称通过。

## 5. 用户审阅与逐图推进

展示最新候选及绝对路径，简要说明关键变化，邀请用户按内容、布局、配色、连线或文字反馈；此时等待审阅。

收到修改意见，先记录原话与不变量，只编辑受影响部分，另存新版本并回查。状态用“待处理、部分处理、已处理、未处理”；修复以实际输出为准。

用户认可后记录确认原话、图号和版本，用户确认与内部质检结论分开记录，仍有缺陷时保留具体问题，不能因认可而宣称缺陷已修复。多图任务接着提供下一幅的模板选择，不能未经选择一次生成余下全部图。用户要求修改skill等其他工作时保留当前图状态，按新指示推进。

## 6. 按需交付

- **图片任务**：交付确认PNG，说明版本与必要的未解决事项；绘图Markdown保存在运行目录，用户要求或有助于复用时再附链接。只要图片时不增加其他交付格式，无需附空PPT路径或无关验证文件。
- **文档插图任务**：全部相关图片确认后，按原任务调用文档技能插入指定位置，保留正文、公式与样式，核对图号、图题、实际尺寸和分页。
- **明确要求可编辑PPT**：仅在图片确认后调用`image-to-editable-ppt`skill，遵循其真实可用流程及必要授权要求。保留只读定稿PNG，文字、形状和连线应为可编辑对象，不能用整图加文字覆盖冒充。按该流程验证PPTX可打开、页数和`validation.json`结果，再交付。

“图片挺好”只确认图片，不自动扩展为PPT制作。原任务已经要求的文档插图或PPT可继续执行，无需重复索取同一授权。最终仅报告实际完成且用户所需的文件，不删除源材料、候选轮次或图片版本。
